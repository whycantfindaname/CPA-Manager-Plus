# Structure And Navigation

## Site Layout

Chinese pages live directly under `apps/docs/`; English mirrors them under `apps/docs/en/`. The paired content roots enforced by `tests/docsContentIntegrity.test.mjs` are:

```text
guide/ gateway/ manual/ deployment/ operations/
migration/ troubleshooting/ reference/
```

For a user-facing page in one of these roots, add or update the same relative path in both languages. Examples are `guide/runtime-model.md` and `en/guide/runtime-model.md`.

`apps/docs/.vitepress/config.ts` is the authority for locale labels, top navigation, sidebars, social links, and local route registration. A local route in that file must resolve to an existing Markdown page; keep advanced configuration and reference groups collapsed unless the information architecture is intentionally changed.

## Page And Asset Rules

- Use VitePress frontmatter for title, description, and home layout metadata. Discovery-critical pages listed in `tests/docsContentIntegrity.test.mjs` require both `title` and `description`.
- Use relative Markdown links between pages in the same locale. English pages must remain under `/en/` when linked through VitePress config.
- Put documentation images in `apps/docs/images/`. Import an image in `<script setup>` when the page needs VitePress bundling, as the two locale `index.md` pages do.
- Keep custom site-wide presentation in `.vitepress/theme/custom.css`; avoid page-specific global CSS unless it is shared by multiple pages.
- Never edit `.vitepress/dist/`; it is generated by `npm run docs:build`.

## Information Architecture

Organize content by the user's task:

- `guide/`: choosing a mode, first use, and mental model.
- `deployment/`: install and runtime-specific procedures.
- `manual/`: daily product operations.
- `operations/`: maintenance, backup, update, and operator actions.
- `troubleshooting/`: symptom-first diagnosis with simple checks before advanced detail.
- `reference/`: capability matrix, FAQ, and releases.

Do not expose internal planning documents or raw release-note paths as primary user navigation.

## Anti-patterns

- Do not add only one language for a mirrored content root.
- Do not add a sidebar or navbar route without the target page.
- Do not promote implementation reports into the primary navigation.
- Do not classify the Live Demo as a deployable panel or runtime mode.
